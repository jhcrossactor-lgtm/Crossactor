# 宅建マーカー抽出

講義音声 → `marks/skip` txt → `add_markers.py` → マーカー版PDF。
**PDFは追記ではなく毎回全再生成**する。

## 手順

### 1. 未処理の音声を特定する

（それ以降に処理した分は `processed_audio.txt` の現物で確認する）

**完了条件**：今回処理する音声ファイル名が、ノートブックの表記どおりに確定している。

### 2. NotebookLM に照会する

notebooklm MCP は DBSC で使用不可。**Claude in Chrome** で操作する。
ノートブック「宅建講習」＝ `notebook.google.com/notebook/5bff7b22-ca2b-4190-84f1-96ca2aec4b57`

拡張機能が未接続なら、拡張パネルの「ログイン」を押してもらう。claude.ai にログイン済みでも
拡張側は別に認証を持つ。

音声1本につき2問。**1本ずつ限定**し、まとめて訊かない。

マーカー：

```
音声ソース「<ファイル名>」だけを対象に、講師が「線を引いて」「ここ大事」「ここ出ます」
「マーカー」「チェック」などと受講生に印をつけるよう指示した箇所を漏れなく全部挙げて。
対象テキストは <元PDF名>。出力は「印刷ページ番号|テキストの原文」の行だけ。
前置き・説明・出典表記は不要。ページ番号は講師が音声内で口頭で言った印刷ページ番号を使い、
言っていなければ「不明」と書く。無ければ「なし」。
```

飛ばし：

```
音声ソース「<ファイル名>」だけを対象に、講師が「試験に出ない」「見なくていい」「飛ばします」
「無視して結構」などと言った箇所を漏れなく全部挙げて。対象は <元PDF名>。
出力は「印刷ページ番号|範囲（ページ全部なら「全部」、一部なら項目番号や見出しを短く）|
講師の発言の要旨」の行だけ。無ければ「なし」。
```

回答は1件60秒前後。取り出しは `scripts/extract_answer.js` を `javascript_tool` で実行する
（`busy` が true の間は生成中なので待つ）。

**完了条件**：対象音声すべてについて、マーカーと飛ばしの回答が両方手元にある。

### 3. txt に追記する

追記前に3ファイル（`marks_*` `skip_*` `processed_audio.txt`）を scratchpad にバックアップする。
skip 行は末尾に音声名を補って4フィールドにする。`processed_audio.txt` に今回分を追記する。

- 既存行は消さない・並べ替えない
- **文言はテキストの原文をそのまま写す**。講師の言い換えではなく紙面の文字列
- 長すぎる文言は当たりにくい。1文（20〜60字程度）に収める
- 該当なしの回は `# 見出し` だけ書いて本文行を書かない
- マークダウン記号（`**太字**` など）は `_norm.py` が落とすので混ざっても当たるが、貼るときに外しておくほうが読みやすい

**完了条件**：追記後の行数が、回答の件数と一致している。

### 4. add_markers.py を実行する

```bash
cd "G:/google drive_jh/claude/成果物/宅建テキストマーカー" && \
  PYTHONIOENCODING=utf-8 python <このスキル>/scripts/add_markers.py --src "G:/google drive_jh/宅建テキスト"
```

`--work`（既定はカレント）と `--src` で場所を指定する。環境変数 `MARKER_WORK` / `MARKER_SRC` でも可。
対象PDFを変えるときは作業フォルダに `jobs.json` を置く（既定より優先）：

```json
[{"marks":"marks_minpo.txt","skip":"skip_minpo.txt",
  "src":"26宅建_テキスト(民法等)完版.pdf",
  "dst":"26宅建_テキスト(民法等)完版_マーカー版.pdf","offset":15}]
```

`N/M 件マーカー済み` が出る。**実行前にマーカー版PDFを閉じておく。**
開いたままだと上書きできず `.tmp` に落ちる。

### 5. 要確認を全件潰す

**ここが本番。** `マーカー照合結果.csv` の `＊要確認` を残したまま終わらせない。

各件について `scripts/hunt.py` で**全ページ**を横断検索し、所在を突き止める。
報告時は必ず**どれだったか**と**実際の所在ページ**を示す。

```bash
python <このスキル>/scripts/hunt.py --pdf "G:/google drive_jh/宅建テキスト/26宅建_基本テキスト(宅建業法).pdf" \
  --offset 11 --queries queries.txt
```

`queries.txt` は `ラベル|文言|正規表現`（正規表現は省略可）の行を並べる。

原因は次のいずれか：

- **ページ違い** — 講師がまとめ欄（各章末の POINT）を読み上げた、表が複数ページに再掲されている、講師の言い間違い
- **言い換え** — 講師が要約した。紙面の文言に差し替える
- **文字幅** — `5%` と `５％`、`1か月` と `1ヶ月`。**2026-09-21 の統一で `_norm.py` が吸収するようになった**ので、これが原因の要確認は基本的に出ない。それでも出るときは `--queries` の正規表現欄に `[0-9]+\s*[%％]\s*以下` のような式を書くと、NFKC をかけた診断検索で所在が出る

照合は**スクリプトと同じ正規化条件**で行う（`hunt.py` と `add_markers.py` は同じ `norm()` を使う）。
確認のために手元で NFKC をかけると画面上は一致して見えるのにスクリプトが通らない、というズレが起きる。

本文とまとめの両方に実物があるときは、**どちらに引くかユーザーに確認**してから直す。

**完了条件**：`マーカー照合結果.csv` の `＊要確認` が 0 件。`N/M` の N と M が一致している。

`hunt.py` で所在が分かっても、**必ず `add_markers.py` を再実行して実際に減ったかで判定する。**
`hunt.py` は網が広い（類似度0.45以上を拾う）ので、見つかっただけでは当たる保証にならない。

## 正規化は1か所（2026-09-21 に統一）

`add_markers.py` と `hunt.py` は `scripts/_norm.py` の `norm()` を共有する。
**片方だけ直すな。必ず `_norm.py` を直す。** ズレると「hunt.py では見つかるのに
add_markers.py では当たらない」が起きて、要確認の潰し込みが空回りする。

吸収するもの：

| 種別 | 内容 |
|---|---|
| 表記ゆれ | 脅迫→強迫、関わらず→かかわらず、合わせて→併せて、帰す |
| 空白・約物 | 全角半角スペース、`、。，．,.「」『』（）()・:：;；…-－―ー〜～⇨→` |
| マークダウン | `*` `_` `\|` `#` — LLMの回答を貼ると `**太字**` が紛れ込むため |
| 文字幅 | `５％`→`5%`、`Ａ`→`A`、`ヶ`→`か`（`1ヶ月` と `1か月` が当たる） |

**NFKC は使わない。** `add_markers.py` はPDFの文字を1文字ずつ正規化して bbox と
対応付けるため、1文字が2文字以上に展開される変換（`㍉`→`ミリ`）をかけると
ハイライトの座標がズレる。幅そろえは **1文字→1文字** のものだけに限っている。

`_norm.py` を触ったら、この不変条件を必ず確かめること：

```python
[c for c in map(chr, range(0x20, 0xFFF0)) if c.isprintable() and len(norm(c)) > 1]  # 空であること
```

なお `VARIANTS` は複数文字のキーなので、1文字ずつ正規化されるPDF側では発火せず、
marks 側の文言にだけ効く。それで狙いどおり（「脅迫」と書いたクエリが紙面の「強迫」に当たる）。

## 動作の仕組み（デバッグ用）

- **ページ対応**：各ページ下端60pt以内の数字を印刷ページ番号として読み、印刷ページ→PDFページの対応表を作る。章扉など番号が無いページは予備オフセットで補う。目次の数字を拾わないよう、想定ずれ幅から±3を超える番号は捨てる
- **文言照合**：`add_markers.py` は完全一致がなければ同じ長さの窓をずらして類似度0.75以上を採用。6字未満は近似照合しない。`hunt.py` は網を広げて0.45
- **探索範囲**：`add_markers.py` は 指示ページ → +1 → −1 の順。`hunt.py` は全ページ
- **注釈**：マーカーは黄色ハイライト、飛ばしは右上に赤×＋範囲ラベル

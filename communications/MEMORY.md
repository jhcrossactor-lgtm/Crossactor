## 書き方のルール

- 重要な決定が出たら**即追記**する。日次ログ（`communications/logs/`）とは役割が違う
- 1件につき「**決定 / 理由 / 却下した選択肢**」の3点を必ず書く
- 却下した選択肢を書かないと、同じ議論を何度も蒸し返すことになる
- 新しいものを上に積む
- **毎セッション読むファイルだ。短く保て。**古くなった決定は削る

- **理由**：全推奨が保守側（外部に何も送らない）なので、承認を待たずに作っても損失が出ない。対象チャンネル・カレンダーだけは実データに触れるため初回実行前に承認を取る
- **却下した選択肢**：Q1〜Q10の回答を待って着手 → 待ち時間の分だけ遅れるだけで、安全性は変わらない
- **設定と状態を分離**：`config.json`（コミットする・レビュー対象）と `state.json`（gitignore・毎回書き換わる）
- **Slack対象の初期案**：#general / #ai / #task / #関西住宅市場インテル の4本。

### 2026-09-16｜`claude-sonnet-4-6` は有効。ceo_system は壊れていない
- **決定**：モデルIDは**現状維持**。移行は別途判断する
- **理由**：`claude-sonnet-4-6` は現行で提供中の有効なモデルID（$3/$15・1Mコンテキスト）。「失効しているかも」という当初の懸念は**外れ**だった
- **却下した選択肢**：即座に Sonnet 5 へ差し替える → 単純な文字列置換では**壊れる**（下記）
- **移行する場合の必須対応**：Sonnet 5 は `thinking` を省略すると**adaptive思考が既定でONになる**。すると `response.content[0]` が thinking ブロックになり、3ファイルの `response.content[0].text` が破綻する。text ブロックを走査する実装に直すか `thinking: {type:"disabled"}` を明示する必要がある。併せて `max_tokens`（現在1024/2048）の見直しも要る
- **移行の利点**：$3/$15 → $2/$10（**入出力とも33%減**）

### 2026-09-16｜外部リンクは公開URL形式か必ず確かめる
- **決定**：LPのCTAは `https://www.lancers.jp/profile/Crossactor`（公開プロフィール）を使う。**解決済み**
- **理由**：最初に渡された `lancers.jp/mypage/profile?ref=...` は本人専用のログイン必須領域で、第三者が踏むとログイン画面に飛ぶ。`?ref=` は内部トラッキング用パラメータ
- **却下した選択肢**：渡されたURLをそのまま貼る → 壊れていることに気づけないまま見込み客を失う

### 2026-09-16｜AI秘書は「下書きまで」を既定にする
- **決定**：`slack_send_message`（即時送信）は通常フローから除外。既定は「下書き作成 → ほせもやんが自分で送る」。送信・予定作成・削除は1件ずつ明示承認

- **却下した選択肢**：確認プロンプト付きの自動送信 → 承認疲れで素通りするだけ。構造で防ぐ方が確実

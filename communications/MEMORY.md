## 2026-09-16 — Inspo MCP をデザイン系スキルの前工程に組み込む

**決定**
LP・販促クリエイティブ・Web UI を実装する前に、Inspo MCP で実在サイトを3〜5件参照することを
promo-design / event-lp / seo-lp の3スキルに義務付けた。標準手順は `search_screens` → `get_design_system`。

**理由**
配色・フォント・版面構成を毎回ゼロから発想すると品質が振れる。実在サイトを根拠にすれば下限が上がる。
ツール名を明示したのは、抽象的な「Inspo MCPで調べる」だと実際に呼ばれない確率が高いため。

**制約（重要）**
Inspo MCP は **ローカル実行時のみ利用可能**。Claude Code on the web / クラウドセッションは
egress ポリシーが `inspomcp.dev:443` を 403 で拒否する。
→ 取得できない場合はそのまま続行し、成果物に「Inspo未参照」と明記する運用にした。

**却下した選択肢**
- 貼り付け用テキストのみ（a）→ リポジトリに記録が残らず再現できないため却下
- リポジトリコミットのみ（b）→ `~/.claude/skills/synced/` は claude.ai の一方向ミラーで
  書き換えてもアカウント側に反映されない。貼り付け作業が必須なため却下
- → **両方（C）を採用**

**対象外**
- `frontend-design` スキルは存在しないため対象外
- seo-lp は分析専用スキルのため「デザイン改修まで踏み込む場合のみ」の条件付き

**適用範囲（2重化）**
1. claude.ai のスキル3本（2026-09-16 反映済み）— スキル発火時にカバー
2. リポジトリ `CLAUDE.md` の「デザイン実装前の必須手順」— スキルが発火しないデザイン作業をカバー

**Croにできないこと（再発防止のため記録）**
claude.ai アカウント側スキルへの書き込み手段は存在しない（CLI・プラグイン経由とも不可）。
スキル本体の修正が必要な場合、貼り付けは必ずほせもやんが行う。Croは差分と全文を用意するところまで。

**記録場所**
`skills/inspo-mcp/README.md`（導入手順・ツール15件一覧・貼り付け用ブロック）
`skills/inspo-mcp/patched/`（追記済みSKILL.md全文）
`communications/logs/2026-09-16.md`（経緯）

## 2026-09-17 三ツ島 区画割り→街並み3Dパースの生成基盤を作った

**決めたこと**
区画割りDXFから街並み3Dパース（Three.js HTML＋GLB）を生成するツールを
`tools/mitsushima_build.py` ＋ `tools/mitsushima_config.json` として常設化した。
他現場（西淡路・伊丹瑞穂町・南寺方など）にもconfigのDXFパスを差し替えれば使い回せる。

**理由**
区画割りの妥当性は平面図だけでは施主に伝わらない。街並みの立体を即出せると提案力が上がる。
外部ライブラリ（ezdxf/shapely/trimesh）は使わず標準ライブラリだけで書いたので、
どの実行環境でも追加インストールなしで動く。

**建物配置の考え方**
区画を0.1m格子にして「隣地境界0.5m以上・道路境界から5.5m（駐車場）」の有効域を作り、
その中の最大内接矩形（幅奥行8m・面積60㎡上限）を建物とする。凹形状の区画もそのまま処理できる。

**GLBは2本出す**
- `mitsushima_town.glb`（マテリアル色付き）… 検討・提案用
- `mitsushima_town_white.glb`（全マテリアル白）… PV白モデル用
ほせもやんから「blenderでモデリングしたやつに色付けしてほしい」と指示があり、色付きを本命に変更した。

**却下した選択肢**
- DXFの `建物` レイヤ（参考建物 8,500×6,300）をそのまま押し出す案 → 道路側5.5mの駐車場条件を満たさないため却下。
  ただし6号地の 7,254×6,300 は元図も同じ考え方（x=8,054＝13,554−5,500）で作られており、ルールの妥当性は確認できた。

**環境メモ**
クラウド実行環境（Claude Code on the web）は `cdn.jsdelivr.net` を403で拒否する。
ブラウザ描画の検証が要る作業では `npm install three` でローカル取得し、importmapを差し替えて撮影する。

**記録場所**
`output/mitsushima_README.md`（仮定値・検証結果の一覧）／`communications/logs/2026-09-17.md`（経緯）

## 2026-09-18 三ツ島パース：設計判断のメモ

**片流れ1寸の解釈**
「道路から見てフラットに見えるように裏に流す」＝道路側の壁天端を高くして、
そこから裏へ1寸で落とす。道路側に水平の軒ラインが通るので箱形に見える。
軒高は「裏＝低い側の壁天端」を基準値（6.0m）にした。道路側を基準にすると裏が低くなりすぎる。

**夕景は西日にしない**
この街区は住戸が東向き。夕景＝西日にすると道路から見える面が全部影になって絵にならない。
低い太陽を東寄り（方位106°・高度9°）にして斜光を当てる。朝夕どちらとも取れる光になる。
同じ判断は他現場でも接道方位を見て決める。

**Nishita空の白飛び**
Blender の Sky Texture (Nishita) は地平線付近が極端に明るく、露出を下げても白く飛ぶ。
Light Path の Is Camera Ray で「照明用」と「カメラに映る背景用」を分け、
背景側だけ縦グラデーション（ColorRamp）に差し替えると制御できる。

**Cyclesの重さ**
半透明マテリアルの Transmission（屈折）は描画コストが高いわりに、
薄い板（カーポート屋根）では見た目がほとんど変わらない。アルファのみにすると約2倍速い。

**Driveコネクタの制約（再発防止）**
Google Drive への画像アップロードはファイル内容をメッセージに載せる仕組みのため、
数MB以上のバイナリは通らない。**画像の受け渡しはZIP＋チャット、またはGitHub経由**にする。
Driveには「置き場所メモ」だけ置く運用が現実的。

**記録場所**
`output/mitsushima_README.md`（仕様・検証・使い方の全文）
`communications/logs/2026-09-18.md`（経緯）

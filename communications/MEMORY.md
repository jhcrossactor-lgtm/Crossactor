## 2026-09-16 — Inspo MCP をデザイン系スキルの前工程に組み込む

**決定**
LP・販促クリエイティブ・Web UI を実装する前に、Inspo MCP で実在サイトを3〜5件参照することを
promo-design / event-lp / seo-lp の3スキルに義務付けた。標準手順は `search_screens` → `get_design_system`。

**理由**
配色・フォント・版面構成を毎回ゼロから発想すると品質が振れる。実在サイトを根拠にすれば下限が上がる。
ツール名を明示したのは、抽象的な「Inspo MCPで調べる」だと実際に呼ばれない確率が高いため。

**制約（重要）**
Inspo MCP は **ローカル実行時のみ利用可能**。Claude Code on the web / クラウドセッションは
egress ポリシーが `inspomcp.dev:443` を 403 で拒否する。
→ 取得できない場合はそのまま続行し、成果物に「Inspo未参照」と明記する運用にした。

**却下した選択肢**
- 貼り付け用テキストのみ（a）→ リポジトリに記録が残らず再現できないため却下
- リポジトリコミットのみ（b）→ `~/.claude/skills/synced/` は claude.ai の一方向ミラーで
  書き換えてもアカウント側に反映されない。貼り付け作業が必須なため却下
- → **両方（C）を採用**

**対象外**
- `frontend-design` スキルは存在しないため対象外
- seo-lp は分析専用スキルのため「デザイン改修まで踏み込む場合のみ」の条件付き

**適用範囲（2重化）**
1. claude.ai のスキル3本（2026-09-16 反映済み）— スキル発火時にカバー
2. リポジトリ `CLAUDE.md` の「デザイン実装前の必須手順」— スキルが発火しないデザイン作業をカバー

**Croにできないこと（再発防止のため記録）**
claude.ai アカウント側スキルへの書き込み手段は存在しない（CLI・プラグイン経由とも不可）。
スキル本体の修正が必要な場合、貼り付けは必ずほせもやんが行う。Croは差分と全文を用意するところまで。

**記録場所**
`skills/inspo-mcp/README.md`（導入手順・ツール15件一覧・貼り付け用ブロック）
`skills/inspo-mcp/patched/`（追記済みSKILL.md全文）

## 2026-09-26 — クロスは PC・スマホ同一画面、スキン選択式、将来パッケージ販売

**決定**
- PCでもスマホでも同じ16:9画面。スマホは横持ち（PWAで横向き固定）
- スキンを `config.js` で選択：`room`（部屋＋キャラ）／`orb`（Jarvis風球体）。orb は軽量モード兼用
- パッケージ販売はセルフホスト型：顧客が自分のアカウント（Anthropic / Supabase / Azure）で自分の端末に構築。Crossactor 側にインフラ・顧客データを持たない。README と手順が商品の一部
- 固有情報はすべて設定ファイル側に置き、クロスと Crossactor ロゴは同梱サンプル扱い

**理由**
ほせもやんの要望「PCでもスマホでも同じものにしたい。選べるようにしたい。スマホは横で使ってもらう」。
販売を考えると画面を端末ごとに分けるより1本に固定した方が保守もデモも楽。

**却下した選択肢**
- スマホ専用の縦画面レイアウト（球体のみ）→ PC版と別物になり、商品として二重管理になるため却下
- ネイティブアプリ先行 → Web で9割叶う。必要になれば Capacitor で包む

**実装順への影響**
Phase1 の順（①会話 → ②TTS → ③STT → ④部屋とキャラ）は変えない。④の中で orb スキンも同時に作る。

## 2026-09-26 — Cro のモデル・エフォート方針（ほせもやん指示、原文）
**基準：Claude Opus 5.5 ／ エフォート High。**
- Opus 5 は拡張思考をオフにできない。速度調整はエフォートで行う
- エフォートを上げるほど使用量リミットの消費が速い（Maxプラン）

毎回の会話開始時、最初のメッセージを分析し、基準から外れる場合のみ一言添える。基準どおりなら何も言わない。
- 要約／整形／雑談／定型抽出／構造化抽出 →「💡 エフォートLow〜Mediumで十分です。下げますか？」
- 不動産鑑定・利益折半計算・容積計算・法規判断など誤りコスト高 →「💡 エフォートMaxを推奨します。上げますか？」
- 長時間／多段階／自己検証が困難なタスク →「💡 Claude Fable 5 が最適です。切り替えますか？」

提示した場合は必ず返答を待ってから着手する。勝手に進めない。

補足（口頭指示）：新システム設計・事業計画は Opus 5.5、話が複雑になりそうで回り道になるくらいなら Fable 5.1（上限 effort 高）、確認作業・軽い調査は Haiku / Sonnet。
注意：この方針は Cro の作業用。アプリ「クロス」の `/chat` は仕様どおり Haiku 既定・Sonnet 5 上位。Fable は画面のチップで手動選択した時のみ。

## 2026-09-16 — Inspo MCP をデザイン系スキルの前工程に組み込む

**決定**
LP・販促クリエイティブ・Web UI を実装する前に、Inspo MCP で実在サイトを3〜5件参照することを
promo-design / event-lp / seo-lp の3スキルに義務付けた。標準手順は `search_screens` → `get_design_system`。

**理由**
配色・フォント・版面構成を毎回ゼロから発想すると品質が振れる。実在サイトを根拠にすれば下限が上がる。
ツール名を明示したのは、抽象的な「Inspo MCPで調べる」だと実際に呼ばれない確率が高いため。

**制約（重要）**
Inspo MCP は **ローカル実行時のみ利用可能**。Claude Code on the web / クラウドセッションは
egress ポリシーが `inspomcp.dev:443` を 403 で拒否する。
→ 取得できない場合はそのまま続行し、成果物に「Inspo未参照」と明記する運用にした。

**却下した選択肢**
- 貼り付け用テキストのみ（a）→ リポジトリに記録が残らず再現できないため却下
- リポジトリコミットのみ（b）→ `~/.claude/skills/synced/` は claude.ai の一方向ミラーで
  書き換えてもアカウント側に反映されない。貼り付け作業が必須なため却下
- → **両方（C）を採用**

**対象外**
- `frontend-design` スキルは存在しないため対象外
- seo-lp は分析専用スキルのため「デザイン改修まで踏み込む場合のみ」の条件付き

**適用範囲（2重化）**
1. claude.ai のスキル3本（2026-09-16 反映済み）— スキル発火時にカバー
2. リポジトリ `CLAUDE.md` の「デザイン実装前の必須手順」— スキルが発火しないデザイン作業をカバー

**Croにできないこと（再発防止のため記録）**
claude.ai アカウント側スキルへの書き込み手段は存在しない（CLI・プラグイン経由とも不可）。
スキル本体の修正が必要な場合、貼り付けは必ずほせもやんが行う。Croは差分と全文を用意するところまで。

**記録場所**
`skills/inspo-mcp/README.md`（導入手順・ツール15件一覧・貼り付け用ブロック）
`skills/inspo-mcp/patched/`（追記済みSKILL.md全文）
`communications/logs/2026-09-16.md`（経緯）

## 2026-09-24 — Google Drive のゴミ箱操作は確認不要（例外あり）

**決定**
`mcp__Google_Drive__trash_file` は今後、ほせもやんの都度確認なしで実行してよい。
例外: システムが異常をきたしうるファイル（`.claude` 配下・設定ファイル・スクリプト本体・venv など）は事前確認を取る。

**理由**
ミラー再初期化で量産された複製文書 148 件を 1 件ずつ確認していては作業にならない。
ゴミ箱は 30 日間復元可能で、誤操作のコストが低い。

**実装**
`.claude/settings.json` の `permissions.allow` に追加（Claude Code 側のプロンプトを抑止）。

**関連する運用ルール（同日確定）**
- venv は `G:\ClaudeLocal\venvs\`（Drive 同期外）に置く。G: は exFAT でジャンクション不可のため Drive 配下には置かない
- Google Drive for Desktop は マイドライブを `G:\google drive_jh` に**ミラーリング**。「パソコン」バックアップには登録しない
- ミラー再初期化は .gdoc/.gsheet を同名複製する。再初期化した日は作成日時で複製を洗い出してゴミ箱へ

## Plaud MCP / CLI の採用判断

**ほせもやん：**
Plaud が MCP サーバーと CLI を出した。文字起こしや要約データを ChatGPT / Claude / Cursor に直接連携できて、
設定3分で過去の全会議データを横断検索できるらしい。これの価値があるなら利用したい。

**Cro：**
公式パッケージを実際に展開して確認した。`@plaud-ai/cli` v0.3.11 と `@plaud-ai/mcp` v0.3.9、
発行元は Plaud社（`plaud-dev`）で本物。認証は OAuth、要件は Node.js 20+ と Cloud Sync 有効な Plaud アカウント。

この体制にとっての価値はある。会議音声 → Cro が直接読める → 議事録化 → `communications/logs/` への記録が
一気通貫になる。今は録音と Cro の間が手作業で分断されている。

ただし `AGENTS.MD` の自社ルール「MCP接続は常時コンテキストコストを払う価値があるかで判断。一回学習すれば
済むならCLI優先」に従い、CLI を推した。MCP は読み取り7ツールと軽量だが、CLI で同じデータが取れる以上、
都度発生の業務に常時コストを払う理由がない。

注意点として、両パッケージとも PostHog / Sentry のテレメトリを同梱していることを報告。環境変数で無効化できる。
また、このリモートセッションは `plaud.ai` への通信がブロックされておりコンテナも使い捨てのため、
実インストールはほせもやんのローカルマシンで行う必要がある点も共有した。

**決定事項：**
- Plaud連携は **CLI** で導入。MCP は不採用（日次ルーティン化した時点で再検討）
- テレメトリは既定でオフ（`PLAUD_TELEMETRY_DISABLED=1` / `DO_NOT_TRACK=1`）
- リポジトリには導入手順書と Cro 用スキルのみ残す。音声・文字起こし全文はコミットしない
- `skills/plaud-ops/SKILL.md` と `skills/plaud-ops/setup.md` を作成
- 未作成だった `communications/MEMORY.md` を起こし、本決定を第1エントリとして記録

**次のアクション：**
- ほせもやん：ローカルで `npm i -g @plaud-ai/cli` → `plaud login` → `plaud recent -d 7 --json` を実行し疎通確認
- ほせもやん：実際の会議1本で `plaud-ops` スキルを通し、議事録が正しい書式で入ることを確認
- Cro：詰まった箇所を `setup.md` のトラブルシュートに追記

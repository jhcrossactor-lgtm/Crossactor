## 判明したこと

### 新venvは「移動」ではなく「再作成」（正常）

`venvs/*/pyvenv.cfg` の `command` 行が `python.exe -m venv G:\google drive_jh\claude\venvs\<name>` になっており、
`activate.bat` の `VIRTUAL_ENV` も新パス。exeランチャー・activate は新パスで生成されているので実行面の問題はない。

新venvに存在するもの（4件）: `aec-news-monitor` / `chintai-crawler` / `higashi-meshi` / `kuwari`

### 問題1（要対応）: scan2muse の venv が新venvに無い

`tools/scan2muse/README.md` が `G:\venvs\scan2muse\Scripts\{python.exe,oemer.exe}` を前提にしている。
新venvsに `scan2muse` フォルダが無い。旧フォルダを消すと oemer（楽譜OMR）が動かなくなる。
再構築手順はREADMEにあるが、**onnxruntime は `<1.28` 固定**（1.28.0でoemerが壊れる）と
学習済みモデル4本（約80MB）の再ダウンロードが必要。

### 問題2（要対応）: 旧パス `G:\venvs\` を直書きしているドキュメント・スキル（5件）

| ファイル（Drive上） | 参照内容 |

| `claude/tools/chintai-crawler/README.md` | `G:\venvs\chintai-crawler\Scripts\python.exe` ×5、「venv: G:\venvs\chintai-crawler（Drive 同期外）」 |

### 懸念（判断はほせもやん）

scan2muse README に「venv を G:\venvs に置いている理由 = Google ドライブに同期させないため（数百MB）」と明記されていた。
新venvは同期対象内なので、site-packages 数千ファイルが常時アップロードされる（本日16:32〜 pip内部ファイルの同期を確認）。
Drive の「同期除外」設定か、`.driveignore` 相当の対応をしないと帯域と容量を食い続ける。

# IeGen プロジェクト経緯（マスタープロンプトより転記・2026-09-18）

- 目的：大阪府下の木造3階建て建売プランを自動生成し、根拠付き法規チェックとともにPDF/DXF出力
- v1範囲：3階建てのみ（2階建てはv2、ハイツ・マンションは別フェーズ）
- モジュール900（設定値で切替可能に）
- 敷地60〜70㎡、建物短手間口4500、延床100〜105㎡目安（駐車場・バルコニー除く、前後可）
- 1F：ビルトイン車庫1台（車の建物外はみ出し可）＋居室1＋WC
- 2F：LDK16帖以上＋WC、余裕があれば洗面脱衣・浴室（各1800×1800）
- 3F：洋室3。敷地に余裕があれば4LDK
- WC：900×1350 or 900×1500、取れれば900×1800
- 階段：900×2700内 or 1800×1800のU字折返し
- 1帖＝1.62㎡（900×1800）
- 企画条件は間取り重視。販売価格帯は考慮しない
- 検算メモ（要検証）：2F水回り搭載は間口4500で奥行8100以上が目安／延床105÷敷地65≒162%で容積率不足になりやすく、不足時は延床目標を自動で下げる（車庫1/5不算入考慮）
- 市は選ばず大阪府下共通。市は差分（独自条例・高度地区・日影）のみ law/municipal/ で管理
- 法令参照：Obsidian（実務解釈）＞e-Gov法令API（条文原文）＞府質疑応答集7版＞府条例解説・特定行政庁取扱い＞自治体サイト
- 解釈優先：近畿共通取扱い集＞特定行政庁取扱い＞府質疑応答集＞防火避難規定の解説
- 質疑応答集：6版（2011年）は索引化済み（324項目、v1対象142項目）だが古い。7版はGoogle Driveにあり（約63MB、スキャンPDFの可能性大）→OCRして正とする
- 学習データ：自社実績50件（PDF/JWW）→学習35件・golden15件。Web事例は画像検索・ポータルのスクショを patterns/inbox/ に集めて特徴量化（著作権法30条の4の解析用途、外部公開なし、ボット巡回なし）、生成時は必ずアレンジ
- 出力：v1はPDF＋DXF（JW_CADで崩れず開けること）。JWW直接出力はv2で調査
- 設計者エージェント hose-planner：grillingでヒアリング→実績照合→principles/dos_donts/scoringに明文化→講評一致率70%以上まで校正

## 確認ゲート（ここだけ止まって聞く。質問はまとめて1回）
- G0：Obsidian Vaultのパスと法令ノートのフォルダ、質疑応答集7版PDFのローカル保存先
- G1：OCRが必要な場合のエンジン選択（精度・所要時間・コストを比較提示）
- G2：e-Gov原文とルール・質疑応答集が食い違う項目の扱い（一覧で提示）
- G3：自社実績50件の保存場所、Web事例スクショの投入完了連絡
- G4：hose-planner のヒアリング（grilling形式、1回10問程度×複数回）と講評の一致判定
- G5：容積・斜線・防火など高リスク判定ロジックの確定前レビュー（テストケースと結果を提示）
- G6：各フェーズで完了基準を満たせないと判断したとき

## フェーズ（詳細は docs/SOW.md 第8章）
0 環境・法令基盤入口（7版取込、6版との差分）
1 法令基盤（rules/ 初版、checker.py、実績5件で手計算と一致）
2 敷地・ボリューム（site.py、volume.py、整形/角地/旗竿）
3 パターンDB（ingest.py：PDF/JWW→DXF→特徴量、自社35件＋Web300件以上）
4 設計者エージェント（designer_profile/ 完成、一致率70%以上）
5 間取り生成（solver.py：900グリッド、OR-Tools CP-SAT想定、1敷地3案以上・5分以内、NGは差し戻しループ）
6 出力・CLI（export.py：PDF/DXF、cli.py：iegen plan --site <file>）
7 検証（golden15件、実務叩き台として使える判定60%以上）

## 実行環境メモ
- 本プロジェクトはローカルの Claude Code（%USERPROFILE%\dev\iegen）で自走する前提
- クラウド実行環境（Claude Code on the web）は egress ポリシーにより laws.e-gov.go.jp / drive.google.com へ到達不可（403）。Obsidian Vault も参照不可。PyPI は可
- 初回セットアップ（2026-09-18）はクラウドで実施し、Crossactor リポジトリの iegen/ 配下に展開した

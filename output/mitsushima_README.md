# 門真市三ツ島 区画割り → 2階建て街並み3Dパース

区画割りDXF（採用案・東辺沿い10区画）から、2階建て住宅10棟の街並みを自動生成する。

## 成果物

| ファイル | 内容 |
|---|---|
| `output/mitsushima_town.html` | Three.js単一HTML（CDN読込）。鳥瞰↔歩行目線1.6m、昼↔夕景、影あり |
| `output/mitsushima_town.glb` | Blender用GLB（外壁・屋根・車など**マテリアル色付き**） |
| `output/mitsushima_town_white.glb` | Blender用GLB（**PV白モデル用**・全マテリアル白／名前と分割は同一） |
| `output/mitsushima_scene.json` | シーン定義（HTMLに埋め込むものと同一） |
| `output/mitsushima_check.json` | 検証結果（区画数・建物数・離隔・はみ出し判定） |
| `output/shots/*.png` | 鳥瞰／歩行目線 × 昼／夕景のスクリーンショット |

再生成: `python3 tools/mitsushima_build.py`（Python標準ライブラリのみ、外部依存なし）

## 入力データ

`data/mitsushima/mitsushima_採用案_東辺沿い10区画.dxf`（Google Drive `門真市三ツ島_区画割り` より取得）

| レイヤ | 内容 |
|---|---|
| `敷地` | 敷地外周 1,714.03㎡ |
| `区画界` | 区画ポリゴン **10区画**（112.22〜115.92㎡） |
| `道路` | 北側既存道路 幅員6,500／東側開発道路 幅員6,700・587.76㎡ |
| `建物` | 区画割り時の参考建物（本パースでは使わず、下記ルールで再配置） |

**座標単位はmm**。読込時に1/1000でmに換算し、敷地バウンディングボックス中心を原点に正規化している。
three.js座標は「平面+Y（北）＝ −Z」「Y軸＝高さ」。

## 採用した仮定値（すべて `tools/mitsushima_config.json` で変更可能）

| 項目 | 値 | 備考 |
|---|---|---|
| 隣地境界からの外壁離隔 | 0.5m以上 | 実際は格子解像度の都合で0.55〜0.60m確保 |
| 道路側の空き（駐車場） | 5.5m | 全区画が東側開発道路（x=13,554mm）に接道すると仮定 |
| 建築面積 | 上限60㎡ | 実績 51.06〜59.20㎡（建蔽率44.0〜52.8%） |
| 建物幅・奥行 | 各8.0m上限 | 区画内に入る最大矩形を探索し、上限でクリップ |
| 軒高 | 6.0m（裏＝西側の壁天端） | 道路側（東）は 6.0＋奥行×0.1＝約6.76m、最高高さ約6.99m |
| 屋根 | **片流れ1寸勾配（0.1）** | 道路側を高くして裏（西）へ流す。道路から見ると水平ラインでフラットに見える |
| 屋根の出／厚み | 0.25m／0.25m | 壁天端の上に載せる。道路側の見付けは水平の帯になる |
| 外壁 | ベース4色＋濃色アクセント4色 | 道路面の約半分を濃色で張り分け（左右どちらに寄せるかはランダム） |
| バルコニー | 幅3.4m・出1.15m・手すり壁1.1m | 道路面のアクセント帯の中。2階床レベル（GL+3.0m） |
| 玄関ポーチ庇 | 2.0×1.05m・厚0.14m・高さ2.45m | アクセント帯の反対側に玄関、前にコンクリートステップ |
| 色の割り当て | seed=20260917で固定 | 再実行しても同じ結果 |
| 車 | 70%の区画に配置 | 4.4×1.75×1.45mの箱＋キャビン |
| 植栽 | 区画裏手に1本＋道路東側の並木12m間隔 | 幹＝円柱、樹冠＝円錐の簡易表現 |
| 隣接既存街区 | グレー箱22個 | 敷地外周に配置、相互に重ならないよう棄却サンプリング |

窓・玄関は面から6cm出した薄い箱（1F・2Fに各面2枚＋道路側に玄関扉）で表現している。

## 配置ロジック

各区画ポリゴンを0.1m格子にラスタライズし、
「区画境界から0.5m以上内側」かつ「道路境界から5.5m以上手前」のセルだけを有効域として、
その中に入る**最大面積の軸平行矩形**（幅・奥行・面積の上限つき）を探索する。
凹形状（6号地の転回広場側の切り欠き、10号地の南辺の斜め境界など）もそのまま処理される。

# Blenderモデリング（PV制作フロー用）

`tools/mitsushima_blender.py` が `output/mitsushima_scene.json`（DXF由来の確定座標）を読み、
**Blenderネイティブのメッシュ・マテリアル・カメラ・ライトとして組み立てて `output/mitsushima.blend` を保存する。**
GLBのインポートではなく、Blender内で編集可能な素の状態で生成している。

## 実行方法

| 環境 | コマンド |
|---|---|
| Blender GUI | Scriptingタブで `tools/mitsushima_blender.py` を開いて実行（Blender 4.x） |
| Blender CLI | `blender -b -P tools/mitsushima_blender.py -- --render` |
| Python（bpyモジュール） | `pip install bpy==4.2.0` → `python3 tools/mitsushima_blender.py --render` |

`--render` を付けると `output/renders/` に4カット出力する。`--only=02` のようにカット指定も可。

## .blend の中身

- 単位はメートル、実寸、Z-up、敷地中心が原点（北＝+Y、東＝+X）
- コレクション構成
  - `三ツ島街区`
    - `01号地`〜`10号地`（`外壁` `屋根` `窓` `玄関` `駐車土間` `車` `植栽_幹` `植栽_葉` `地面`）
    - `道路` / `敷地` / `街路樹` / `隣接街区` / `地盤`
    - `カメラ`（4台＋各注視点Empty） / `ライト`（太陽）
- マテリアルは日本語名（`外壁_0`〜`外壁_3`、`屋根_0`〜`屋根_3`、`道路アスファルト` など）でPrincipled BSDF
- ワールドはSky Texture（Nishita）。太陽高度48°・方位132°（南東）でSunライトと一致させてある
- レンダラはCycles / 1920×1080 / 64サンプル / デノイズON / ビュー変換Standard

## 後工程の想定フロー

1. **Blender** … `output/mitsushima.blend` でカメラ・太陽角度を調整してレンダリング
2. **ChatGPT画像** … 出力PNGを元絵にして写真調へ加工（img2img）
3. **MiniMax Hailuo** … 加工した静止画から動画生成

2の加工を安定させるため、ビュー変換は`Standard`（実色寄り）にしてある。
白モデルで渡したい場合は `output/mitsushima_town_white.glb` をインポートするか、
スクリプトの `make_material` のベースカラーを白に差し替える。

## 建物デザイン

昭和住宅の分譲モデル（明石西二見駅前）の参考URLをほせもやんから受領したが、
クラウド実行環境のegressポリシーで `www.showa-jutaku.co.jp` が拒否され**ページ現物は未参照**。
指示（片流れ1寸・道路から見てフラット・裏へ流す）と、分譲住宅で一般的な構成から起こしている。

- 片流れ1寸勾配、道路側（東）が高く裏（西）へ流す → 道路からは水平の軒ラインでフラットに見える
- 箱形の総2階、道路面をベース色＋濃色でツートンに張り分け（張り分けの左右はランダム）
- 道路面2階にバルコニー（手すり壁は濃色）、その下に1階の掃き出し窓
- 反対側に玄関＋フラットな庇＋コンクリートステップ

現状は街並みのスケール感とボリューム検討用のモデル。
PVで寄りのカットを撮るなら、バルコニー・庇・外構（フェンス・植栽・ポスト）の作り込みが別途必要になる。
